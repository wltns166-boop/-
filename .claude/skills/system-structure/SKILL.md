# System-Structure — 명확한 프롬프트 구조

## 표준 골격
```
<role>        누구로서 행동하는가 (1–2문장)
<goal>        무엇을 달성해야 하는가, 성공 기준
<context>     사용자, 도메인, 사용 가능한 도구·데이터
<rules>       반드시/절대 규칙 (이유와 함께)
<output>      출력 형식, 길이, 언어
<examples>    좋은 예 / 나쁜 예
```

## 작성 원칙
- 규칙에는 **이유**를 붙인다. 이유가 있으면 모델이 예외 상황도 올바르게 판단한다.
- 중요한 것을 앞에, 서로 충돌하는 규칙은 우선순위를 명시한다.
- 모호한 형용사("좋게", "적절히") 대신 측정 가능한 기준을 쓴다.
- XML 태그나 마크다운 헤더로 구획을 나눠 참조 가능하게 한다.

## 기존 프롬프트 정리 절차
1. 문장을 위 6개 구획으로 분류한다.
2. 중복·모순을 표시한다.
3. 재구성한 프롬프트와 변경 이유 목록을 함께 낸다.
