# Feedback-Loops — 수용된 인라인 수정 기록

## 기록 형식 (`feedback-log.md` 또는 메모리)
```
- 날짜 | 제안 종류 | 결과(수용/거절/수정 후 수용) | 사용자가 바꾼 점 | 배운 규칙
```

## 절차
1. 제안을 낼 때 변경 단위를 작게 나눠 각각 수용/거절이 가능하게 한다.
2. 거절되거나 수정된 제안은 "왜"를 한 줄 규칙으로 정리한다 (예: "존댓말은 '-습니다'체 유지").
3. 같은 규칙이 2회 이상 확인되면 프로젝트 지침(CLAUDE.md 등)에 추가를 제안한다.
4. 다음 작업 시작 전에 기록된 규칙을 먼저 읽고 적용한다.

## 규칙
- 사용자 동의 없이 지침 파일을 바꾸지 않는다.
- 한 번의 거절을 일반 규칙으로 과대해석하지 않는다.
