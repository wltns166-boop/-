# Constraint-Spec — 엄격한 출력 형식 제한

## 제약 명세서
| 항목 | 예 |
|---|---|
| 형식 | JSON만, 코드블록·설명 문장 없음 |
| 스키마 | 필드명, 타입, 필수/선택, 허용 값(enum) |
| 길이 | summary ≤ 100자, items 3–5개 |
| 언어 | 한국어, 숫자는 아라비아 숫자 |
| 금지 | 추측성 값, 빈 문자열 대신 null |

## 적용 방법 (강한 순서)
1. API의 구조화 출력/도구 스키마 기능이 있으면 그것을 사용한다.
2. 없으면 프롬프트에 JSON 스키마 + 올바른 예시 1개를 넣는다.
3. 응답을 코드로 검증(파싱, 스키마 검사)하고 실패 시 오류 메시지와 함께 1회 재요청한다.

## 규칙
- "가능하면"이 아니라 "반드시"로 쓴다. 단, 정보가 없을 때의 처리(null)를 반드시 정의한다.
- 제약끼리 충돌하지 않는지 확인한다 (예: 5개 필수인데 100자 제한).
